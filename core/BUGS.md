# Баги общего ядра INU (`inu_gta_core` = `core/` Blender-версии)

Найдены 2026-09-27 при переносе Map IO (IDE / IPL / IMG) в 3ds Max. Каждый
пункт подтверждён: запуском на тестовых копиях архивов, замером на архивах
игры (только чтение) или исходниками игры (re3 / reVC). Ядро Blender-версии —
та же копия, поэтому всё ниже есть и в Blender.

Статус: пункты 1–8 исправлены в `inu_gta_core` 2026-09-27 (`img.py`,
`ide.py`, `game_versions.py`), см. «Исправления» в конце. Эти три файла были
одинаковы во всех копиях ядра, поэтому переносятся простой заменой файлов.

---

## 1. IMG VER2 (SA): каталог при росте затирает первый файл

**Где:** `img.py` — `ImgWriter.__exit__` → `_write_directory`, а также
`replace_or_add`.

**Что:** каталог VER2 лежит в начале файла (8 байт + 32 байта на запись) и
пишется поверх того, что там есть. Новые записи дописываются в конец файла, а
каталог растёт в начале. Проверки «каталог налез на данные первого файла» нет,
и первые файлы архива не переносятся.

**Замер (только чтение):** сколько новых файлов влезает до порчи первого файла.

| Архив | Записей | Запас до первых данных | Новых файлов до порчи |
|---|---|---|---|
| gta3.img (ваниль SA) | 16316 | 2168 байт | 67 |
| gta_int.img (ваниль SA) | 2484 | 376 байт | 11 |
| gta3.img (GTA Silent Hill) | 3617 | 406488 байт | 12702 |

**Повтор:** новый архив (`create_img`), в него 100 файлов через `ImgWriter`.
Первый файл (`f000.dff`) после записи испорчен.

**Последствие:** «Export to IMG» больше 67 новых моделей в ванильный gta3.img
(или больше 11 в gta_int.img) портит первые файлы архива.

## 2. `rebuild_img` портит любой архив от 64 записей

**Где:** `img.py` — `rebuild_img` → `create_img` + `ImgWriter`.

**Что:** `create_img` пишет заголовок в 8 байт без места под каталог.
`ImgWriter` кладёт первый файл в сектор 1 (байт 2048). Каталог из N записей
занимает `8 + 32·N` байт, при N ≥ 64 это больше 2048, и каталог затирает
первый файл. Для gta3.img (16 тыс. записей) затираются сотни секторов данных.

**Последствие:** «Rebuild» и «Rebuild after export» портят архив всегда, кроме
совсем маленьких.

## 3. IMG VER1 (III / VC): удаление и замена пишут заголовок SA в .img

**Где:** `img.py` — `remove_file` и `replace_or_add`. Версия архива не
проверяется, вызывается `_write_directory`, то есть запись в VER2-формате.

**Что:** в начало `.img` (там данные первого файла) пишется `VER2` + каталог.
Сам `.dir` не обновляется.

**Повтор (копия VER1-архива):**
- `.img` после `remove_file` начинается с `b'VER2'`;
- первый файл испорчен;
- ридер ядра после этого считает архив VER2 и читает каталог из `.img`, а
  игра читает старый `.dir`.

## 4. `ImgWriter` читает размер записи VER2 не так, как ридер

**Где:** `img.py` — `ImgWriter.__enter__`: `struct.unpack_from('<II', raw, 0)`.

**Что:** в записи каталога размер — два u16 (streaming size, archive size).
`_parse_dir_records` так и читает (`<IHH`), а `ImgWriter` склеивает оба u16 в
одно u32. Если archive size не 0, размер получается огромным. Тогда проверка
«новые данные влезают в старое место» всегда проходит, и замена на месте может
записать больше старого места — поверх следующих файлов.

**Статус проверки:** по коду. На проверенных архивах (ваниль gta3.img,
gta_int.img, gta3.img GTA Silent Hill) archive size = 0 у всех записей, поэтому
на них это не срабатывает. У архивов, собранных инструментами, которые заполняют
второе поле, — сработает (сам `_parse_dir_records` в докстринге описывает такие
архивы: stream=2053, archive=2053).

## 5. IDE для III / VC: строки `objs` / `tobj` без числа мешей

**Где:** `ide.py` — `_format_obj_line` и `_format_tobj_line` (ветка не-SA).
Через них пишут `write_ide` и `mapsync/ide_doc.py` (Add to IDE).

**Что пишет ядро:** `865, ap_tower, ap_buildings2, 299, 0`.

**Что требует игра:** `865, ap_tower, ap_buildings2, 1, 299, 0` — четвёртое
поле обязательно, это число мешей.
- re3 `CFileLoader::LoadObject` и reVC `CFileLoader::LoadObject` /
  `LoadTimeObject`: `sscanf(line, "%d %s %s %d", &id, model, txd, &numObjs)`,
  затем `switch(numObjs)` только с `case 1/2/3`.
- Ванильные файлы: VC `data/maps/airport/airport.ide` —
  `865, ap_tower, ap_buildings2, 1, 299, 0`; III
  `data/maps/comnbtm/comnbtm.ide` — `2075, Jetty, compark, 1, 163, 0`.

**Последствие:** строка ядра читается игрой как `numObjs = 299`. Ни одна ветка
`switch` не срабатывает: дистанция и флаги остаются мусором, а
`SetNumAtomics(299)`. Докстринг `_format_obj_line` («III/VC only know the
5-field single-mesh form») неверен.

## 6. Имя записи IMG длиннее 23 символов пишется без нуля в конце (мелкое)

**Где:** `img.py` — `_encode_directory_records`: имя обрезается до 24 байт,
и 24-символьное имя остаётся без завершающего нуля. `ImgWriter.add` длинные
имена не отклоняет.

**Игра (reVC `CStreaming::LoadCdDirectory`):**
- `direntry.name[23] = '\0'` — 24-й символ теряется;
- если точка стоит дальше 20-го символа (`dot - name > 20`), запись
  пропускается («is too long»).

Blender-экспорт проверяет длину сам (≤ 23), но ядро молча пишет битое имя.

## 7. Текст предупреждения на русском внутри ядра (мелкое)

**Где:** `game_versions.py` — `check_game_mismatch_warning` возвращает готовую
русскую строку. В интерфейсе на английском (Max-версия) её нельзя перевести.

## 8. `upsert_ide`: формат SA для любой игры, timed-записи попадают в `objs`

**Где:** `ide.py` — `upsert_ide`. Форматтеры вызываются без `game`, поэтому
файлы III/VC получают строки SA (см. п. 5). Новые timed-записи (`is_timed`)
дописываются в секцию `objs` через `_format_obj_line`, и `time_on` / `time_off`
теряются.

## Исправления (2026-09-27)

Проверено скриптом на временных архивах: все сценарии выше плюс 3000
добавлений поверх 100, rebuild на 700 записях, круговой прогон строк IDE
(формат → `_parse_obj_line`) для III / VC / SA.

- **1, 2.** `ImgWriter` при закрытии (VER2) переносит в конец архива файлы,
  на которые залезет выросший каталог (`_relocate_under_directory`).
  Новый параметр `reserve_entries` резервирует место под каталог заранее:
  `rebuild_img` передаёт число записей, и архив получается плотным, без
  переносов.
- **3.** `remove_file` для VER1 переписывает `.dir`, для VER2 затирает нулями
  освободившийся хвост каталога. `replace_or_add` теперь обёртка над
  `ImgWriter` (VER1 / VER2 и перенос из п. 1 — одним кодом).
- **4.** `ImgWriter` читает каталог через `_parse_dir_records`.
  `_encode_directory_records` пишет размер как `<HH` (streaming, archive = 0),
  как в ванили, и отклоняет размер > 65535 секторов.
- **5.** `_format_obj_line` / `_format_tobj_line`: для III / VC всегда пишется
  форма с числом мешей (`1, dd, flags`; при доп. дистанциях `2`/`3`, как в
  `switch` игры). SA — без изменений.
- **6.** `ImgWriter.add` отклоняет имена не ASCII и длиннее 23 символов
  (`ValueError`); кодировщик режет имя до 23 байт, ноль в конце остаётся
  всегда. Правило reVC про точку (`dot - name > 20`) не проверяется: при
  лимите 23 оно срабатывает только для имён без точки или с расширением
  короче 3 символов, а в re3 такой проверки нет.
- **7.** Строка идёт через `_t()` (ленивый `T` пакета-хоста, как в
  `textdata_lint`); ключ с `{0}`/`{1}`, форматирование после перевода. Без `T`
  (Max, тесты) возвращается русский текст — хосту нужно добавить перевод.
- **8.** `upsert_ide(..., game=)`: формат по игре; timed-записи идут в `tobj`
  (секция создаётся при необходимости); запись, найденная не в той секции,
  переносится в правильную.

Не исправлено: `textdata_lint.check_ide` проверяет длину строки в формате SA
для любой игры (строки III / VC на 3 символа длиннее). Этот файл в копиях
ядра различается, поэтому правка делается в каждой копии отдельно.

## Исправления и синхронизация (2026-09-30 — 2026-10-01)

Ядро синхронизировано с `INU_tools/core` Blender. Разделы выше сохраняют
историю найденных проблем и прежних проверок.

- IMG: замена/удаление первой записи, освобождение места и пересборка;
  операции с VER1/VER2 учитывают каталог и сохраняют посторонние записи.
- `col_library`, `img_remove`, `img_routing`: удаление отдельных COL-записей,
  защита используемых TXD, запись модели и LOD в их собственные архивы.
  Общий LOD без собственного архива записывается в архив каждой HD-модели;
  неудачная запись его DFF/TXD блокирует последующие IDE/IPL.
- IDE: комментарии в строках `peds`, сохранение чужих секций и строк;
  определение реально загружаемых IDE по `default.dat`, `gta.dat`,
  `gta_int.dat`, `gta_vc.dat`, `gta3.dat` вместо полного сканирования корня.
- Mapsync: неизменённые строки сохраняются, масштаб III/VC не теряется;
  `lod_index` пересчитывается при изменении состава строк. Имена LOD III/VC
  формируются по правилу игры; смещение и поворот существующего LOD SA
  сохраняются относительно его модели при Add.
- Архивы: общий порядок загрузки `gta_dat.img_load_order` для SA/III/VC;
  `map_files` использует то же правило.
- `fs_ci`: пути из файлов игры разрешаются без зависимости от регистра
  букв на Linux/macOS; идентичность путей используется при маршрутизации.
- TXD: у D3D9 палитра читается без лишней перестановки R/B; PAL4 читает
  32 записи по 4 байта вместо 256. Историческая компенсация D3D8 в
  Blender сохранена: при переносе ядра в другой хост учитывать его адаптер.
- `paths.ipl`: раздельные реальные flags/spawnRate, 12 колонок VC,
  координаты VC /16 при чтении и ×16 при записи, десятичная точность без
  `.4g` и научной записи. Неизменённые строки сохраняются при повторной записи.
- SA nodes: новые узлы сливаются с импортированным районом в одном файле;
  при добавлении автоузлов перед пешеходными пересчитываются индексы и ссылки.
  Такой пересчёт требует экспорта всех 64 районов с разобранными секциями;
  частичный небезопасный экспорт останавливается до перезаписи района.
- Анализ карты: файлы DFF/TXD из modloader и TEXDICTION удовлетворяют
  проверке наличия ресурсов, не создавая ложных конфликтов архивов;
  модель DFF и TXD проверяются по соответствующим расширениям.

Проверки выполнялись без запуска Blender/3ds Max. Поведение интерфейса
и редактирование точек в настоящем Blender требуют проверки пользователем.

## Не баг (проверено)

- **`ipl.is_lod_name` — «lod» в любом месте имени.** Правило намеренно широкое.
  Замер по ванильным IDE SA: у 210 LOD-моделей «lod» стоит не в начале
  (`CornerStore_LOD`, `cs_lodbit_01`, `a51_lod_jetroom`…), поэтому более
  строгое правило их бы потеряло.

## Заметка о скорости

- **`img.extract_file`** на каждый вызов перечитывает весь каталог архива. Для
  многих файлов подряд использовать `ImgReader`.

## Compiled NODES: добавление и удаление точек — исправления 01.10.2026

Раньше экспорт сетки читал параллельные свойства по текущему индексу вершины,
сохранял старые связи и игнорировал добавленные рёбра. Теперь адаптер Blender
хранит стабильную идентичность в INT/POINT атрибуте (в Blender 2.83 — в
vertex_layers_int), разрешает обычный Extrude/Subdivide и строит граф по рёбрам.
Ядро paths_graph.py создаёт NaviNode/NaviLinks, длины и согласованные секции,
сохраняет направления и полосы при однозначном разбиении старого участка.
Физические ID и внешние ссылки пересчитываются; ссылки на удалённые узлы
исключаются вместе с соответствующими элементами всех массивов связей.

Изменение прежних ID требует всех 64 районов. До записи проверяются адреса,
число связей (до 15), навигационная ёмкость (1024 записи в ванильном районе),
совпадение сжатых XY и сериализация. Неизвестные ненулевые хвосты, удаление
узла с внешней заглушкой, неоднозначные совпавшие дубликаты и потерянные
атрибуты блокируют экспорт. Старые уже изменённые сцены требуют переимпорта.
Добавленные отдельные узлы без рёбер остаются несвязанными. Категории мешей
нельзя объединять; вершины навигации нельзя добавлять/удалять вручную.

Проверено на исходных 64 файлах GTA SA: неизменённый граф сохраняется,
добавление и удаление автомобильной точки обновляет собственные и соседние
адреса. Нормализация неиспользуемых pointer-слов в writer существовала раньше.
Проверка настоящего Blender и игры остаётся ручной; многoфайловая запись
не гарантирует откат при позднем сбое ОС/диска.


## Compiled NODES: проверка настоящего Blender — 01.10.2026

После разрешения пользователя запущен Blender 5.1.2 в фоновом режиме с
factory settings и аддоном из репозитория. Все 20 проверок прошли без
пропусков: 11 сценариев NODES и 9 IFP, включая 3 прежних bpy-пропуска.
Проверены Extrude/Subdivide, дублирование/удаление, сохранение и открытие
.blend, повторный импорт DAT, экспорт 64 районов в Object Mode и при
одновременном Edit Mode всех автомобильных сеток.

Найден и исправлен сбой Blender-адаптера при экспорте из Edit Mode:
Attribute.data не предоставляет значения, хотя update_from_editmode
обновляет геометрию. Идентичность вершин читается из живого BMesh int layer;
миграция неизменённой старой сцены тоже работает в Edit Mode. Само ядро
этим исправлением не менялось. Общий pytest: 1807 passed, 4 skipped.
Игра и 3ds Max не запускались; поздний сбой многoфайловой записи по-прежнему
не гарантирует откат всей партии.
